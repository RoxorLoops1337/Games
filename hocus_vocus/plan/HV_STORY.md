## 1. Rules every string here obeys

Every string in sections 2 to 4 and 6 was machine-checked in a scratch harness against these rules (from the bible section 6, the
current `hocus_vocus_narrative` and `hocus_vocus_content` suites, and the Echowake plan's Appendix A section 2). Paste them as
written.

| Where | Rule |
|---|---|
| All copy | printable ASCII; no em or en dash, no ` - ` or `--` as a dash; no tabs or line breaks; no double spaces; no leading or trailing space; a space after `. , ! ? ; :` before a letter; straight quotes only; no doubled words; British spelling (colour, favourite, towards, kerb, draught, practised) |
| Banned words (checked) | Echowake words (echo, hush, verse, fable, keeper, chime, ballad, journey, treasure, champion, peddler, campfire, wake, awake, the land, hall), Inkwoven words (ink, page, book, paint, brush, quill, scroll as a word, write, blank, author, chapter, editor, edition, margin, archive, library), Japanese folklore words, animal products (silk, pearl, felt, cream, milk, butter, cheese, egg, honey, wax, leather, wool, fur, bone, shell, feather), death words (kill, die, dead, death, blood), admin words (form, fee, invoice, booking, contract, schedule, manager, tax, email, paperwork), alcohol and smoking, "vegan", "plant-based", "healthy", "diet", real platforms and shows. Note: "felt" is avoided even as a verb and "die" even as the singular of dice, so a token scan cannot misfire |
| Event title | at most 40 characters, unique, never equal to a reserved name (H16) |
| Event text | 60 to 220 characters, unique; names no hero unless the event has `when.hero`, and then it names that hero by DATA `name` |
| Choice label | 4 to 48 characters, unique in its event; a `req.hero` choice names its hero; a label with `(fight)` has a fight; a certain fight says "fight"; a label naming "N gold" equals `req.gold` |
| Choice cost | 3 to 32 characters; `N gold` equals `req.gold` and is charged; `Lose a card` removes one in every outcome; a curse that is not certain says may, maybe or might; `Hurts the lead hero` hurts `who:'front'` in every outcome; `N Vox` is charged in every outcome (the old `N Echo`) |
| Outcome text | 40 to 300 characters, ends with `. ! ? ' "`, distinct within its choice; names only the hero of its `req.hero` or of the moment; "<number word> gold" matches a gold op of that size and "<number word> hexes" matches a `paint` op of that `n` (unless the outcome teaches a Spell); no "N HP" in prose |
| Story entry | title 5 to 40, unique; text 400 to 700 characters, one paragraph, exactly 6 sentences by the suite's splitter, starts with a letter (the drop cap), ends with `. ! ?`; shared entries never match `/Jasmin|RoxorLoops|RawClaw|Andy/` |
| Tip | 30 to 110 characters, a sentence, no digits (an `X` cost is allowed), unique |

## 2. The Detours (all 48 events)

### 2.1 How to apply

Field keys: `L<n>` is `choices[n].label`, `cost` is `choices[n].cost`, `O<n>.<m>` is `choices[n].out[m].text`. The last column ends with the
unchanged ops in square brackets, written in the engine's own words so the implementer can compare them with `data_events.js`: `ink`
is Vox, `paint N` unmutes N hexes, `front` is the lead hero, `red` is the pink gem, `addBrush` teaches a Spell. The names in brackets
after ids are the display names they now carry: enemies from `HV_ENEMIES.md`, curses from `HV_HEROES.md` 2.5, Spells from bible 4.5,
the four fixed Charms from decision D2-3. Fights use only the Act's own enemies, exactly as before.

The file header comment of `data_events.js` changes with it: "the Fables (event tiles)" becomes "the Detours (event tiles)", "12 per
verse" becomes "12 per act", the FLAG PATHS block reads "fox_spared: set by `fox_in_the_snare` (Act I, untangle the gull chick)...
The gull grows up: a chick in Act I, a young gull with a stolen goat mask in Act II, a grown gull who sings in Act III", the hero-moment line
reads "Jasmin and the Perfect Voice (Act I), RoxorLoops and the First Beat (Act II), RawClaw Hears the Mix (Act III), Andy Checks the
Floor (any act)", and the Tone line reads "Tone: silly, warm and heartfelt. Vox is the map resource (op `ink`), Spells are the one-use map
tools (op `addBrush`), unmuting a hex is op `paint`, and the Gloss is the polish that mutes the world."

#### `intro`: One, Two, Testing

> In the Soundlands, voices are magic: a sung note opens a cherry blossom, a beatboxed kick makes the cobbles bounce, and a bass line can roll a hill over in its sleep. Then came the Gloss, a kind little filter made to help one nervous singer feel brave, until everybody turned it up so far that it smoothed everything flat. Now the world is going on mute: buskers lip-sync, birds tweet in perfect tune, and nobody sings along. But two voices were never smoothed, a little wobbly, a little late and completely real. They pack the van, tape Jordan's tour poster in the window and step up to the mic. One, two, testing: the speakers crackle, somebody breathes in, and the beat is about to drop.

#### `ch1_intro`: Blossom Bay

## 5. Social, Share and Support

### 5.1 Principles

1. The game never talks to the network. Links are ordinary anchors the player taps; Share uses the device's own share sheet or the
   clipboard. No `fetch`, no `XMLHttpRequest`, no beacon, no embedded player, no remote image, no remote font, no tracking pixel, no
   follower counts (the hygiene suite bans the network and external URLs; section 5.8 says how the owners' URLs pass it).
2. Nothing opens by itself. A link opens only on a tap or a key press, always in a new tab (`target="_blank"`,
   `rel="noopener noreferrer"`), so the tour in the game's tab is untouched.
3. Gentle, never pushy: the follow row appears on calm screens only (title, Tour Bus, settings, end screens), never in a fight, on the
   map or during a Detour; no pop-up asks for a follow; Support is never shown after a lost tour.
4. Platform names appear only as the five link labels (bible H3); no platform logos are drawn (trademarks): each link is a text pill
   with a small coloured dot, alternating Jasmin pink and RoxorLoops green.
5. A button whose URL is empty is not rendered, so today's build (all URLs empty) shows the handle line and Share only.

### 5.5 Behaviour

- Links: `UI.followPanel(mode)` builds one anchor per non-empty URL in the order of 5.3:
  `mk('a', { href: url, target: '_blank', rel: 'noopener noreferrer', class: 'hv-link', 'aria-label': ... }, dot, label)`. The tap
  is a normal navigation in a new tab; the game does not intercept it, count it or remember it. The anchor gets the existing button
  sound (`ui_click`) through the shared button styling only; no new sfx id.
- Share: `UI.share()` runs only inside the tap handler. If `navigator.share` exists it calls
  `navigator.share({ title, text, url })`; a rejection named `AbortError` (the player closed the sheet) is silent; any other rejection
  falls back to the clipboard. Without `navigator.share` it calls `navigator.clipboard.writeText(text + ' ' + url)` and toasts the
  copied or failed string. `url` is `DATA.LINKS.game` or, when empty, `window.location.origin + window.location.pathname` (so a seed
  in the query string is never shared by accident). Both calls sit in try/catch; nothing is stored.
- Support: an anchor like the links (`DATA.LINKS.support`), styled as a primary pill with the relic icon `heart` (an existing icon id).
- Empty states: a link with an empty URL is not rendered; with all five empty, the sheet and the tab show the no-links line; Share
  always works (it needs no URL from the owners).
- Accessibility: every control is a real `a` or `button` with an aria label; focus order heading, pills, Share, Support, Close; the
  sheet traps focus like every overlay and closes on Esc.
- Audio: opening a link sends the page to the background; the existing visibility handling suspends the music, so nothing new is
  needed. Fullscreen is left by the browser when the new tab opens, which is expected.
- Saves: no new storage key and no new profile or run field (bible H14). Links are never shown in a fight, on the map or in a Detour,
  so a tap can never strand a half-finished node; from pause, the run is already saved by the existing flow.

### 5.6 On phones

- Hit targets: every pill and button is at least `var(--hit)` (44 CSS px divided by the stage scale), with 8 stage px gaps, so a
  thumb never hits two links at once.
- Portrait "Play anyway" (stage at about 0.3 scale): the title footer shows only the `Follow the duo` button and `Share`; the sheet does
  the rest. The sheet's pills wrap to two columns.
- New tab on a phone: iOS and Android open the platform app when it is installed (universal links) and the browser otherwise; either
  way the game's own tab keeps the tour. In an installed home-screen app (standalone display mode) `target="_blank"` opens the system
  browser, which is also fine.
- Share on a phone opens the native share sheet (messages, chat apps, the platforms themselves); on a desktop without `navigator.share`
  the clipboard path runs.

### 5.7 Implementation sketch (for the UI plan; `js/ui.js`, presentation layer)

```js
  const LINK_ORDER = [['website', 'Website'], ['youtube', 'YouTube'], ['facebook', 'Facebook'], ['tiktok', 'TikTok'], ['instagram', 'Instagram']];
  const SHARE_TITLE = 'HOCUS VOCUS: A Vocal Magic Adventure';
  const SHARE_TEXT = 'I just played HOCUS VOCUS: A Vocal Magic Adventure, with RoxorLoops and Jasmin. Still human.';
  function shareUrl() { const L = DATA.LINKS || {}; return L.game || (window.location.origin + window.location.pathname); }
  function copyShare() {
    const s = SHARE_TEXT + ' ' + shareUrl();
    try { navigator.clipboard.writeText(s).then(() => api.toast('Copied. Go on, show someone.', 'good'), () => api.toast('Could not copy here. The address bar has the link.', 'warn')); }
    catch (e) { api.toast('Could not copy here. The address bar has the link.', 'warn'); }
  }
  api.share = function () {
    try {
      if (navigator.share) { navigator.share({ title: SHARE_TITLE, text: SHARE_TEXT, url: shareUrl() }).catch((e) => { if (!e || e.name !== 'AbortError') copyShare(); }); return; }
    } catch (e) { /* fall through to the clipboard */ }
    copyShare();
  };
  api.followPanel = function (mode) { /* heading, portrait canvas, handle line, pills for non-empty URLs, Share, Support (unless mode === 'gameover') */ };
```
