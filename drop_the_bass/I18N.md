# Drop the Bass: translations (English, Danish, Dutch, German)

Codes: `en` (the source), `da`, `nl`, `de`. House rule applies here too: never write an em dash, in code, English or translations.

## How it works
- `js/i18n.js` exports `t(key, en, vars)`, `tn(key, n, one, many, vars)`, `setLang`, `getLang`, `onLang`, `LANGS`, `detectLang`, `initLang`, `setLangPref`, `getLangPref`, `langReady`, `registerDict`, `registerData`, `getData`.
- English lives in the code: `t('hub.play', 'Play')`. For other languages `t` looks the key up in `js/lang/<code>.js`; a missing key falls back to the English given in the call, so the game always runs.
- `js/lang/<code>.js` is imported on demand when the language is set (English players never download it). `js/lang/<code>_data.js` is an optional overlay for the names and descriptions of the data tables (see `getData`); a missing file is fine.
- Preference: `profile.settings.lang` is `'auto'` (default: follow `navigator.languages`, Norwegian reads as Danish, anything else is English) or `en|da|nl|de`. An explicit choice is also stored under the localStorage key `drop_the_bass_lang` so the first paint before the profile loads already uses it (an explicit profile choice wins over the key, `auto` removes the key). `document.documentElement.lang` follows.
- `main.js` awaits `initLang` before building any screen, and on a language change calls `app.rerender()` (hub: `app.hub.render()`, title: rebuilt). Battle canvas text calls `t()` every frame, so it follows by itself. `app.setLangPref(pref)` is the one entry point the UI uses. The picker is `langPicker(app, withAuto, redraw)` in `ui_hub.js` (settings modal, and the first title screen without the Auto button). Names are native: English, Dansk, Nederlands, Deutsch (no flags).
- Anything cached with its text baked in (sprites, canvases, DOM built once) must be rebuilt when the language changes: subscribe with `onLang(fn)` or build the text inside the render function.

## Adding a string
1. Write the call with static literals: `t('tour.wave_n', 'Wave {n} of {total}', { n, total })`, plurals `tn('band.gear_bag', n, '{n} piece', '{n} pieces')`.
2. Run `node tools/dtb_i18n.mjs` (regenerates `js/lang/en.js`, reports problems). Then `node tools/dtb_i18n.mjs --stub` adds the new key to da, nl, de (English text, to be translated).
3. Never build a key or the English text at run time (`t('x.' + id, ...)`, `t(k, 'a ' + b)`): the tool lists these as "dynamic" and cannot extract them. Put variable parts into `{placeholders}`. Literals joined with `+` across lines are fine.

## Key rules
`area.name` in lowercase, digits and underscores, at least one dot: `^[a-z0-9_]+(\.[a-z0-9_]+)+$` (`hub.play`, `run.tip.lane_2`). The area is the screen or module. One key, one English text: the same key twice with different English is an error (use two keys or the same text). Never reuse a key for a different meaning, and do not rename keys casually: a renamed key loses its translations.

## Translating
- Edit `js/lang/da.js`, `nl.js`, `de.js` (`export default { 'key': 'text', ... }`). Keep every key, change only the right-hand side. `--stub` rewrites the file sorted and drops comments, so keep notes elsewhere.
- Keep every `{placeholder}` exactly (`{n}`, `{name}`); you may reorder them.
- Plurals are one string with a bar: `'{n} ting|{n} ting'` = singular|plural (`n === 1` picks the first). Exactly one bar, same as English.
- Use the same words as the data overlay for the same thing (turret, remix, relic names). No em dashes. A string equal to the English (longer than 12 characters) is reported as untranslated.
- In the stroke font (big words, floaters, HUD) the text is upper-cased: `ß` becomes the capital sharp s, `æ ø å ä ö ü é è ê ë ï ó ú á í` and the typographic quotes and the euro sign are drawn. Letters outside `STROKE_EXTRA` in `doodle_kit.js` fall back to the hand font, which is fine but looks different.

## Checks
- `node tools/dtb_i18n.mjs --check` verifies da, nl, de against `en.js`: missing and extra keys, placeholders, plural bars, em dashes (errors, exit 1), untranslated English (suspicious, `--strict` makes it an error).
- `node tests/drop_the_bass_i18n.test.mjs` (part of `npm run test:dropbass`): API behaviour, the tool on a fixture, translation structure, stroke font coverage, no em dash in any `t()` source. With `DTB_I18N_STRICT=1` it also demands that all three files exist, hold every key of `en.js`, and that `en.js` is current.
- After adding or removing files in `js/lang`, run `node tools/dtb_make_manifest.mjs` (the service worker precache walks `js/`, so `js/lang/*.js` are included).

## Line length (German and Dutch are long)
English is the budget, translations run about 30 percent longer (German compounds up to 2x for single words: Einstellungen, Bestenliste, Geschwindigkeit). Rules for UI: no fixed pixel widths on text, let buttons grow (`white-space: normal` or wrapping), prefer short verbs on buttons (Play, Los, Spil), keep stroke-font words under 14 characters (the floaters and `text()` fall back to the hand font beyond 14 and 16), leave room for 2 lines in cards and the tip bar, and check de at 390 px wide. Translators: prefer a shorter synonym over an abbreviation, and `-` is a fine word break in compounds.
