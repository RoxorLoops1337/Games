# GRAFTWORK UX SPEC (council memo, UX designer). All numbers are logical px at 1280x720.

Findings: Drag today = hold 12px, drop above PLAY_LINE 420, spring k=45 drag/17 rest, hover y 540 scale 1.18, neighbour push 62/22/8. Hand cards are 54 to 64% scale (118 to 141 px wide) so card text is under 11px: THE biggest readability gap. No tilt/shadow/arrow rules, Esc opens settings, no pause menu, no fullscreen, no layout registry. app.tooltip is single-line title + 16px body at pointer, no pinning, no keyword parsing.

## 1. Card drag and play feel
- Pick-up: press then move >8px (or hold 120 ms). Touch: >10px, finger offset kept so the card sits 70px ABOVE the finger.
- Lift tween 90 ms EASE.out: scale to 0.95 (hand-of-5 rest 0.64), shadow ellipse offset y+14 blur 18 alpha .45 (grows with lift), on top; hand closes the gap with the 17/s spring.
- Follow: critically damped spring on position, stiffness 520, damping 45.6 (~0.1 s settle, no overshoot). Tilt rot = clamp(vx/2400, -0.22, 0.22) rad smoothed k=14/s; squash scale x 1+min(|v|/9000, .04). Reduced motion: no tilt/squash, stiffness 1200.
- Aim arrow only for target:'enemy' cards once the card crosses PLAY_LINE-40 (380). Origin = card top centre. Quadratic Bezier, control point (mid x, min(y0,y1)-120). End snaps to the nearest valid enemy's centre within 90px of the pointer else follows the pointer. 14px dashed 3px stroke + 12px arrowhead; valid = lamp gold, no valid hover = vellum 50%. Marching dashes 40px/s (static if reduced motion).
- Valid targets: gold 4px bracket corners + 8% fill + name plate; invalid/dead enemies dim to 55%. 'all' cards: all enemies bracketed. 'self'/'none': full-width play-zone band y150-420 glows alpha .10 with "Release to play".
- Drop zones: play line y=420 with 40px hysteresis (arm <400, disarm >440). Single living enemy: release above the line auto-targets. Several enemies and no snapped target: card returns to hand with toast "Pick a target" and enters sticky select mode. 'all' Overload cards: confirm chip "Play Overload? 25% shatter" Play/Back, 3s timeout back to hand.
- Cancel: release below y440, right click, Esc (cancels drag only), second finger tap, or drag back over the hand strip. Cancel = card flies home 160 ms EASE.out + 4px settle bounce, sfx uiBack.
- Click-to-play: click selects (rises to y470, scale 1.18, gold edge); click again plays (self/AoE) or click an enemy; with 1 living enemy second click plays. Keys 1..0 select, Enter/Space plays, Tab/Arrows cycle targets.
- Touch: tap selects and raises the card to a preview position (y400, scale 1.0, full text) with a PLAY button (120x52) and a Cancel x; tap an enemy to target. Drag also works. Long-press 350 ms shows keyword tooltips.
- Hand fan: n<=4 s .72 (158w); 5-6 s .66 (145); 7-8 s .60 (132); 9-10 s .54 (119). Spread max 940 wide centred 622 (152..1092), step = min(cw, (940-cw)/(n-1)); n=10 step 91. Arc y = 626 + off^2*1.6 (n>6) else 2.4; rot = off*(n>6 ? .022 : .032), off = i-(n-1)/2. Hover: card to y520, scale 1.22 (top >= 150), rot 0; neighbours pushed +-70 (dist1), +-30 (dist2), +-10 (dist3). 40 ms intent delay when pointer >1500 px/s; hover hit area = visible strip only (not the lifted card) to stop jitter. No hand reorder (decision).
- Cannot play: card stays, 6-frame x shake +-6px over 220 ms, red flash on the cost orb, reason chip above the card 1.2 s ("Need 2 energy", "Unplayable", "Jammed: +1 cost", "No valid target"). Unplayable cards dim to 70% with a lock badge (shape, not colour only), still hoverable and readable.

## 2. Readability rules
- Minimum text 14px for anything the player must read in combat; 12px only decorative; 20+ for numbers that decide play. Resting hand cards show cost, name (>=13px), type glyph and the KEY NUMBER only; full effect text appears on hover (hover card enlarged so effect lines >= 15px; on desktop after 250 ms idle enlarge to 0.95).
- Contrast: body text vs panel >= 7:1; never vellum on vellum; text over art gets a 3px suture stroke; dim states keep text >= 4.5:1 (lower saturation + pattern, not alpha under 55%).
- Tooltips: open after 150 ms, pin beside the item (right else left, never under the pointer or off screen, max 2 stacked). Order: keywords on the hovered card, then statuses. Max width 320, body 16px, title 19px. Touch: long-press 350 ms pins until next tap; a "?" in pause opens the glossary. Keyboard focus shows the same tooltip.
- Glossary highlight: keywords in card text (Vulnerable, Block, Exhaust, Retain, Weak, Burn, Tithe, Strain, Shatter, Echo, ...) dotted-underlined in the keyword colour with a small shape glyph; hover lists each definition. Every number carries a "why" line: "Base 6, +3 Strength, x1.5 Overload = 13".
- Intent: 28px icon + 24px bold number with contrast stroke + "x3" hit count + move name (13px) under the nameplate on hover, always when <=4 enemies. Hidden = "?" with tooltip "Unknown intent".
- Status stacks: 26px icons in rows, count 14px bold bottom-right with 3px stroke, good = top row, bad = second row; duration statuses show a pip arc; colorblind setting adds a corner shape (triangle up good, down bad). Overflow > 8 collapses to a "+N" chip opening a list.

## 4. Pause menu
Esc (when not dragging/modal) and a visible pause button (44x38) on map, combat, reward, graft, shop, forge, event. Panel 420x560 centred: Resume (default focus), Settings, Fullscreen toggle ("Fullscreen: On/Off"), Deck, Controls and Glossary, Abandon run (2-step confirm "Lose this run? Progress counts as defeat"), Quit to title (saves; confirm only mid-combat). Combat pauses logical timers. Esc closes it; arrows/Tab navigate; B/Start on gamepad.
Fullscreen: el = document.documentElement; request = requestFullscreen || webkitRequestFullscreen; exit = document.exitFullscreen || webkitExitFullscreen; state from document.fullscreenElement || webkitFullscreenElement; listen to fullscreenchange and webkitfullscreenchange to sync the button and call app.resize. F key toggles (not in a text field). iPhone Safari has no element fullscreen: hide the button there and show "Add to Home Screen for fullscreen" in Help; iPad supports it. Requests must run inside a user gesture (pointerup/keydown), so set app.pendingFs and process it in the pointerup listener, never from the canvas tick. The browser eats Esc to exit, so keep the button and sync state. Title: fullscreen button top right 1210,16,52,44 with an icon and "F" hint, plus a menu entry below Settings.

## 5. Input and accessibility
Keyboard: 1..0 select, Enter/Space play/confirm, Tab/Arrows cycle targets, E end turn (confirm), P potions, D deck, X draw pile, F fullscreen, Esc cancel then pause, ? help. Gamepad: d-pad/stick cycle, A confirm, B cancel, Y end turn, Start pause; hint strip only when a pad is detected. Colorblind: school glyph shapes, status corner shapes, distinct intent silhouettes (sword, shield, wing, skull). Reduced motion: no tilt/squash/arrow march, hit-stop 0, shake 0, tweens 1 frame. Text scale steps 100/125/150 with reflow (replace the single Large toggle). End turn safety: if energy > 0 and any playable card remains, show confirm chip "End turn with 2 energy and 3 playable cards?" (Enter confirms; button re-arms after 400 ms; double-click on touch ignored). No undo for plays; dropping a card below the line is always safe.

## 6. Top 15 fixes (priority)
1 Card legibility (resting = cost/name/glyph/number; hover = full text >= 15px). 2 Pause menu with Esc + visible button everywhere. 3 Fullscreen on title and pause (webkit, iOS handling, F key). 4 Layout registry + overlap test (1..6 enemies x 0..10 cards). 5 Drag feel (spring, tilt, shadow, offset above finger). 6 Aim arrow with snap and valid brackets. 7 Play-line hysteresis + auto-target for single enemy. 8 Tap-to-select preview + PLAY button on touch. 9 Keyword underline + pinned tooltip stack with "why" lines. 10 Cannot-play feedback (shake + reason chip). 11 End turn confirm. 12 Intent: icon + number + hit count + name always visible. 13 Status stacks: rows, "+N", colorblind shapes. 14 Hover stability (strip-only hit area, intent delay, push 70/30/10). 15 Text scale 100/125/150 + reduced motion coverage for all new fx.
